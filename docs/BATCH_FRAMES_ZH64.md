# zh.64 批量出片

入口：编辑器 → 导出图片 → 应用当前边框到多张照片。首页“批量出片任务”用于重新打开任务。

## 使用流程

1. 在一张照片上调整单图边框、署名、纸色和边距。
2. 设置批量画质（1080/2048/4096px）和标题：各模板默认、统一当前标题、各文件名。画质是源照片最长边上限，不放大小图；成品外边框可能增加总尺寸。
3. 手动配方备注默认不复制，只有明确开启才统一应用。
4. 系统相册最多选择 30 张可解码图片，重复 URI 去重。
5. 查看前三张成品预览，再开始保存。每张独立生成文件，原图不覆盖。
6. 可以取消后续处理、继续待保存项、仅重试失败项，或选择历史任务。

## 任务行为

- 每张照片读取自身 EXIF，模板标题和署名按所选规则应用。
- 逐张解码、渲染、编码并释放位图；预览仅小图，不保留 30 张原图。
- 任务记录以版本化 JSON 和 AtomicFile 保存，进程结束后通过历史任务恢复。
- 已成功项不再处理；继续和失败重试分别处理 pending / failed。
- 用户取消允许正在处理的一张完成，保留已保存作品，不删除原图。
- 单项读取或保存失败被记录，后续照片继续；内存不足或检测到极低剩余空间时停止后续处理。
- Android 10+ 根据任务唯一输出文件名查找本应用已发布成品，避免中断后盲目重复保存；输出仍采用应用既有 Pictures/Fudge 保存目录。
- 没有新增上传、在线遥测或自动发送作品。

## 当前边界

本版支持单图模板，批量拼图分组尚未实现。首次选择通过系统相册，用户已导入到系统媒体库的相机照片可以从中选择。只有前三张生成预览。原图授权可能失效；失效项显示错误，重新选图创建任务，当前没有逐项替换来源的编辑界面。

任务执行与编辑页面分离，但没有新增前台服务，锁屏/后台遇到系统终止时需要重新打开任务继续。记录中的已完成项不因用户后来删除成品而自动重新导出。

2026-10-12：assembleDebug、lintDebug、testDebugUnitTest 通过，共 133 项测试。新增 6 项批量测试，包括实际 JPEG 生成及无效来源失败，重试后成功输出路径不改变，以及取消前未处理项保持 pending。
